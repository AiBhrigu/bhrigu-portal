# BTC Cosmographer multi-body local RC usability and information-design targeted repair v0.1

## Scope

This repair changes only the isolated `/crypto-astro/btc/local-rc` presentation and its acceptance harness. It does not change `/crypto-astro/btc/live`, public routing, source evidence, market methodology, payment, accounts, or backend runtime.

## User-facing repair

- The page shell now follows the actual route: annual Astro overview, significance follow-up, Astro × BTC comparison, Bitcoin Protocol topic switch, or return to the saved Astro topic.
- Follow-up and return states are projected as focused answers instead of repeating the full annual report.
- In an Astro × BTC bridge, the market layer appears first because it answers the current question; the astronomy layer remains independent.
- Annual windows are rendered chronologically as cards, with significance rank shown separately.
- The complete station/ingress chronology remains available but is collapsed by default.
- Internal route tokens, RC state and exact SHA move into a diagnostic disclosure.
- The primary and continuation forms have visible labels, help text, keyboard focus styles, and a fragment target that brings the new answer into view.
- A continuation composer is rendered after the answer.
- The layout uses the 61.803% / 38.197% information ratio as a functional summary/evidence hierarchy, not as decoration.

## Preserved contracts

- multi-body routing and chronology;
- Cyrillic-safe detector;
- unique transition counting;
- Russian morphology;
- six-state semantic corridor;
- compact route and Astro memory packets;
- local environment gate and `noindex` membrane;
- no causal, forecast, price-target, or trading-signal claim.

## Acceptance

The local workflow must prove:

1. existing static and six-turn semantic acceptance;
2. exact production build;
3. desktop `1440×1100` and mobile `390×844` traversal of all five Russian corridor states;
4. English annual-overview parity on both viewports;
5. dynamic shell correctness;
6. market-first bridge ordering;
7. focused follow-up and compact return projection;
8. five chronological window cards with separate ranks;
9. collapsed transition and diagnostic disclosures;
10. visible labels, continuation composer, no horizontal overflow, answer heading in the first viewport, and no severe browser errors;
11. `404` when `BTC_LOCAL_RC` is absent.
