# BTC Market Cosmographer Free Question Corridor Public Launch and Real User Request Acceptance v0.1

## Product decision

The public product is `https://www.bhrigu.io/crypto-astro/btc`.

The GitHub Pages Crypto-Astro surface remains a technical data, proof, and reporting source. It is not the promoted user product.

## Accepted product split

### Landing

`/crypto-astro/btc`

- retains the five deterministic example routes;
- retains the current static snapshot, proof, fallback, and full field read;
- exposes a free BTC question composer inside the first viewport;
- sends free questions to the dedicated dialogue route.

### Live dialogue

`/crypto-astro/btc/live`

- uses the existing accepted static source loader;
- uses the existing deterministic question router and snapshot composer;
- uses the existing market envelope and Snapshot Memory;
- separates the user turn from the Cosmographer turn;
- presents a concise answer before the full technical field;
- keeps Φ-field, Memory, and Evidence available by explicit disclosure;
- requires no account and no payment.

## Colour contract

- deep navy and ink: field depth and page background;
- ivory: primary reading text;
- celestial blue: structure, axes, borders, active controls;
- muted violet: protected or supporting context;
- gold: labels, semantic emphasis, and limited accents only.

Gold must not carry the entire hierarchy.

## Preserved boundaries

- no replacement of the current static source chain;
- no change to the accepted question router, composer, or market envelope algorithms;
- no raw provider rows or private corpus exposure;
- no new public API route;
- no payment or paid Question activation;
- no forecast, price target, trading signal, or investment recommendation;
- no direct write to `master`;
- merge only after exact-head CI and visual acceptance.

## Deployment truth

Implementation and merge do not by themselves prove production publication. Production verification remains a separate exact-SHA evidence step. If the existing Vercel quota blocks deployment, the accepted current public corridor remains available and the new implementation must remain source-anchored without claiming it is live.
